# 练耳 Web 程序 · 设计文档

- 日期：2026-08-24
- 状态：已评审通过，待转实现计划
- 目标平台：移动端优先的 PWA（纯前端、可离线、本地存储）

---

## 1. 目标与范围

### 1.1 目标用户

会乐器但耳朵弱的业余音乐学习者。能看谱演奏、认识基本乐理，但听不出和弦、扒不出旋律、唱不准。**不具备固定音高，且不以习得固定音高为目标。**

### 1.2 成功标准

跟完课程后，学习者应能：

1. 听旋律能扒出来（说出/写出音级并在乐器上找到）
2. 听出和弦进行（说出级数走向，分辨大小七和弦）
3. 视唱能唱准（看谱即唱、脑内旋律能准确唱出）
4. 节奏能听写且稳定

### 1.3 使用节奏

每天 20–30 分钟，正式练习。走完 P1–P4 阶段预计 **6–9 个月**。

### 1.4 非目标（明确不做）

- 不训练固定音高（成人基本不可习得，见 2.1）
- 不做卡拉 OK 式演唱评分（音色、颤音、表现力）
- 不内置真实商业录音（版权 + 体积 + 难度不可控）
- 不做账号系统与云同步（第一版）
- 不做社交、排行榜、好友对战
- 不做用户自选练习内容的入口（见 7.6）
- 不做吉他/特定乐器的专门支线

## 2. 研究依据

每条标注证据强度，避免把教学法主张当成实证结论。

### 2.1 成人无法习得真正的固定音高 —— 强

关键期假说相关研究（Deutsch、Levitin 等）表明固定音高的习得高度依赖早期音乐接触与语言背景，成人训练难以达到真正的绝对音高。但**相对音高可训练至很高水平**。

→ **设计后果**：全部训练锚定相对音高。所有题目问的是"在这个调里是什么功能"，从不问"这是什么绝对音名"。

### 2.2 调性语境重编码音高 —— 强

Krumhansl 的探针音（probe-tone）实验显示，同一物理音高在不同调性框架下被听者赋予截然不同的稳定性/功能判断，且被试间高度一致。音高在调性音乐中是以**层级功能**而非绝对频率被表征的。

→ **设计后果**：每道题必须自带调性语境（§6.1）。孤立播放两个音训练的是一个在真实音乐中用不上的表征。

### 2.3 音程法的失败模式 —— 中（教学法论证，非 RCT）

Karpinski《Aural Skills Acquisition》(2000) 系统论证：以孤立音程为基础的训练导致学习者依赖歌曲联想（"大二度 = 生日快乐开头"）逐个音程向前推算，在真实旋律中因速度和语境切换而崩溃。他主张以音级功能为基础。

→ **设计后果**：T 轨以音级功能为核心，不设独立的"音程识别"训练。音程作为音级关系的派生结果自然获得。

→ **诚实说明**：这是权威教学法论证，其证据等级低于 2.1 与 2.2，不应被表述为实验结论。

### 2.4 Audiation：唱是内化的必经环节 —— 中

Gordon 的音乐学习理论主张 audiation（脑内听到）是音乐理解的核心，且遵循"脑内听到 → 唱出 → 写下"的进阶。识别（选择题）不等于内化。

→ **设计后果**：三模态设计（§6.3），且知识点毕业要求三模态齐平（§8.3）。

### 2.5 交错练习优于分块练习 —— 强

Rohrer & Taylor 等的研究表明，交错练习（interleaving）虽然会降低练习期表现，但显著提升保持与迁移。分块练习制造"学会了"的错觉。

→ **设计后果**：调度器强制交错规则（§7.4）。

### 2.6 间隔效应与检索练习 —— 强

间隔重复优于集中复习；主动检索（testing effect）优于重复暴露。且**在接近遗忘临界时成功检索带来的记忆增益最大**。

→ **设计后果**：掌握度模型以可提取性 R 驱动复习到期（§7.1），且强度增益项含 (1−R) 因子。

### 2.7 合意困难（Desirable Difficulties）—— 强

Bjork：使学习期变难的操作（间隔、交错、变异、生成）通常提升长期保持。

→ **设计后果**：语境强度阶梯（§6.1）、变异预算（§6.2）、2-down-1-up 难度阶梯（§7.4）。

### 2.8 知觉学习的特异性与迁移 —— 强

知觉学习常表现出对训练刺激条件（音区、音色、任务）的高度特异性。刺激变异性可促进迁移，但**过早引入变异会损害初始习得**。

→ **设计后果**：变异预算机制（§6.2）——变异轴随熟练度逐个开放，先分块后变异。这是本程序与市面练耳 app 的核心差异之一。

### 2.9 自适应心理物理程序的收敛点 —— 强

2-down-1-up 阶梯法收敛于约 71% 正确率。

→ **设计后果**：单题难度调节采用该规则（§7.4），使难度自动停在能力边界而非舒适区。

### 2.10 双任务负荷 —— 中

音高与节奏同时处理会超出工作记忆容量。

→ **设计后果**：T/H/R 三轨独立推进并独立评估，仅在阶段实战关中合并（§8.2）。

## 3. 架构

### 3.1 分层

```
┌─────────────────────────────────────────┐
│  UI 层 (React, mobile-first)            │  只渲染，不含音乐逻辑
├─────────────────────────────────────────┤
│  Session Runtime                        │  练习会话状态机
├──────────────────┬──────────────────────┤
│  Scheduler       │  Mastery Model       │  纯函数
├──────────────────┴──────────────────────┤
│  Exercise Generators                    │  (spec, seed) → Exercise
├─────────────────────────────────────────┤
│  Music Core                             │  纯函数、零 IO
├─────────────────────────────────────────┤
│  Audio Engine    │  Pitch Detector      │  脏边界
├─────────────────────────────────────────┤
│  Storage (Repository 接口)               │  可替换实现
└─────────────────────────────────────────┘
```

### 3.2 关键边界约定

| 约定 | 理由 |
|---|---|
| `MusicCore` 不知道 Web Audio 存在，产出声明式 `PlaybackPlan` | 换音色/换合成方式/以后换采样，不影响任何音乐逻辑 |
| `AudioEngine.play(plan)` 只执行清单，不懂乐理 | 同上，且使播放层可被 mock |
| `Generator(spec, seed) → Exercise` **必须确定性** | 测试可断言具体题目；线上问题凭 seed 复现 |
| `Scheduler(mastery, curriculum, today, seed, minutes) → SessionPlan` 是纯函数 | "今天练什么"这个最易出 bug 的决策可脱离 UI 全量测试与仿真 |
| `Repository` 是接口 | 第一版 IndexedDB；以后接云端不动上层 |
| **课程是数据不是代码** | 改课程不改逻辑；课程本身可被校验测试 |

### 3.3 目录结构

```
src/
  music/          纯领域模型（无依赖）
  exercises/      各类题目生成器
  scheduling/     掌握度模型 + 调度器
  audio/          Web Audio 引擎 + 音色定义
  pitch/          麦克风音高检测 (AudioWorklet)
  session/        会话状态机
  storage/        Repository + IndexedDB 实现
  curriculum/     课程数据（声明式配置）
  ui/             React 组件
```

### 3.4 技术栈

- React + TypeScript + Vite
- 原生 Web Audio API（不用 Tone.js —— 避免调度黑盒，节奏轨需要对时钟的完全控制）
- AudioWorklet（音高检测）
- IndexedDB（经薄封装）
- vite-plugin-pwa
- Vitest（单测 / 仿真）+ Playwright（e2e，移动视口）

## 4. 音乐领域模型

### 4.1 唱名体系

底层统一使用**首调音级**（movable do）。小调采用 la 基唱名。

**理由**：对无固定音高的学习者，固定调唱名会把"音高名"与"调内功能"绑死，恰好摧毁本程序要训练的表征（§2.2）。

显示层提供三种皮肤，底层同为一个 `ScaleDegree` 枚举：

| 皮肤 | 示例 |
|---|---|
| 唱名 | `do re mi fa sol la ti` |
| 简谱 | `1 2 3 4 5 6 7` |
| 级数 | `^1 ^2 ^3 ^4 ^5 ^6 ^7` |

切换皮肤不影响任何逻辑与进度数据。

### 4.2 核心类型

```ts
Pitch           { midi: number }              // 绝对音高，仅音频层使用
ScaleDegree     'do' | 'ra' | 're' | 'me' | 'mi' | 'fa' | 'fi'
                | 'sol' | 'le' | 'la' | 'te' | 'ti'
Key             { tonic: PitchClass, mode: 'major' | 'minor' }
Chord           { degree: RomanNumeral, quality, inversion, extensions }
Progression     Chord[]
RhythmPattern   { meter, events: { onsetBeats, durBeats, accent }[] }
PlaybackPlan    { events: { atSec, freqHz, durSec, timbreId, gain }[] }
```

`PlaybackPlan` 是 `music/` 与 `audio/` 之间唯一的数据契约。

## 5. 知识点

掌握度追踪的原子单位。不是"课程第 5 课"，而是可独立追踪、可独立复习的能力点。

```
degree:mi          大调 3 级
degree:le          降 6 级
chord:V7           属七和弦
prog:I-V-vi-IV     和弦进行
rhythm:synco-8     八分切分
```

每个知识点在**三个模态**上各有一份独立的掌握度状态（§7.1）。

## 6. 训练核心

### 6.1 调性语境引擎

每道题播放前先建立调中心。**语境强度是随难度递减的参数**——本程序最重要的难度阶梯。

| 等级 | 形式 | 训练的能力 |
|---|---|---|
| L0 | 完整终止式 ii–V–I（块状和弦） | 依赖外部语境识别音级 |
| L1 | 短促 V–I | 弱化语境依赖 |
| L2 | 仅主音持续低音（drone）贯穿全题 | 在低音上自行定位功能 |
| L3 | 开头给一次主音，随后消失 | **在脑内维持调中心** |
| L4 | 语境在题目中途撤走 | 调性记忆的极限 |

L3–L4 才是真正的相对音高能力。设计意图是逼迫学习者从"靠外部拐杖"过渡到"内部持有调中心"。

**已确认**：阶梯做满到 L4，不在 L3 封顶。

**R 轨的语境（P-2b-R 增补）**：节奏不需要调中心，R 轨的 L0–L4 是节拍器逐级撤走——L0 两小节预备拍加全程节拍器，L1 一小节预备拍加全程，L2 只在强拍响，L3 只有预备拍，L4 节拍器在内容前 40% 后撤走。问「强拍在哪、一小节几拍」的题（拍号、找 beat 1、弱起、混合拍子）改用**中性节拍器**：点击不分强弱、预备拍固定 4 个感知拍（L0 为 8 个）、L2 与 L4 都只在内容最初 3 个感知拍响，从小节中间开始的内容先去掉前导空拍，免得节拍器替学习者说出答案。速度以感知拍计：x/4 是四分音符，6/8 是附点四分。哪些题用中性节拍器、各级细则见 P-2b spec §7.1。

### 6.2 变异预算（抗特异性）

每道题可在以下轴上随机化：

| 轴 | 取值 |
|---|---|
| 调 | 12 个 |
| 音区 | ±1 个八度（P-2b 修订：原 ±2 八度会把持续低音推到听阈之下；整份 plan 另行八度折叠到 MIDI 36–96，见 FWD-4） |
| 音色 | ≥4 种（钢琴类、弦乐类、人声类、电子类），全部 Web Audio 合成 |
| 速度 | 阶段相关区间 |
| 力度 | 区间随机 |
| 呈现方式 | 旋律式 / 和声式（和弦题） |

**但不能一次全开**（§2.8）。每个知识点的 `variationLevel`（0–6）决定当前开放到第几个轴，**开放顺序固定**：

| `variationLevel` | 新开放的轴 |
|---|---|
| 0 | 无。固定 C 大调、钢琴音色、中音区、中速、中力度、默认呈现方式 |
| 1 | 调（12 个） |
| 2 | 音色 |
| 3 | 音区 |
| 4 | 速度 |
| 5 | 力度 |
| 6 | 呈现方式（旋律式 / 和声式） |

顺序依据是对迁移的贡献大小：换调直接攻击调特异性，收益最大，故排第一；力度与呈现方式影响最小，排在最后。

**熟练度下降 → `variationLevel` 自动回退一级**（§7.3），已开放的轴随之收回。

音色全部由 Web Audio 合成（加法合成 + 包络，少量 FM）：零加载体积、零版权风险。

### 6.3 三轨道 × 三模态

**三条轨道**：T（音级）、H（和声）、R（节奏）。

**三个模态**：听辨、唱、听写。

视唱不是独立轨道，是每条轨道上都要走的模态。

| 模态 | T 轨 | H 轨 | R 轨 |
|---|---|---|---|
| **听辨** | 播放 → 点选是哪个音级 | 播放 → 点选功能/进行 | 播放 → 点选节奏型/拍号 |
| **唱** | 给语境 → 唱出目标音级 | 唱琶音、唱低音线 | 念节奏 / 打拍 |
| **听写** | 播放 3–8 音短句 → 输入音级序列 | 播放进行 → 输入级数序列 | 播放小节 → 输入节奏型 |

**听写额外训练工作记忆容量**（从 3 音扩到 8 音），这是"听歌能扒出来"的直接前置能力。

### 6.4 反馈设计

即时反馈对知觉学习是关键的，但**反馈内容比反馈时机更重要**。

答错时**不是**弹出"❌ 正确答案是 mi"，而是：

1. 立刻重放主音 → 再放刚才那个音（趁错误还在耳朵里时做对比）
2. 屏幕上把"你选的音级"与"正确音级"同时标在音阶条上
3. 提供「再听一次慢速版」按钮

答对时给简短确认即可，不打断节奏。

### 6.5 重练入口

唯一的用户主动入口：**「重练刚才错的这组」**。不影响主线调度状态，仅作即时巩固。

## 7. 掌握度模型与调度器

### 7.1 掌握度状态

每个 `(知识点, 模态)` 组合一份独立状态：

```ts
MasteryState {
  stability: number       // 遗忘时间常数（天）
  difficulty: number      // 该点对该用户的难度 0–1
  variationLevel: 0..6    // 当前开放到第几个变异轴（§6.2）
  contextLevel: 0..4      // 当前语境强度 L0–L4（§6.1）
  window: Attempt[]       // 最近 20 次尝试
}
```

**可提取性**：`R(t) = exp(-Δt / stability)`

当 `R < 0.85` 时该点到期待复习。

### 7.2 更新规则

- **答对**：`stability *= 1 + a·(1 − difficulty)·(1 − R)`

  `(1 − R)` 项使**接近遗忘时成功检索带来最大增益**（§2.6），这是间隔效应的机制而非任意倍数。

- **答错**：`stability = max(minStability, stability · c)`，`difficulty` 上调。

**不使用现成 FSRS/SM-2 库**：那些为陈述性记忆卡片调参，且无法承载变异等级与语境等级的门控。自写透明模型可全量单测与仿真。参数 `a`、`c`、`minStability` 等集中在一处配置，便于日后依据 `Attempt` 数据回调。

### 7.3 门控与回退

- **升级**：`stability` 过阈值 **且** 最近窗口的**平均阶梯档位 ≥ 阈值**（窗口至少 8 次）→ 开放下一变异轴 / 提升语境等级
- **降级**：窗口内连续错误 → 自动退回上一级

> **P-2 修订**（建模决策 4）：原文写「窗口正确率 > 90%」。这与 §2.9 冲突——2-down-1-up 把观测正确率锁在约 71%，高于它的正确率门槛永不可达，升级永不发生。改为平均阶梯档位：学习者在当前等级下能吃住多难的变体，才是该升级的信号。为此每次尝试记录它所在的阶梯档位（`Attempt.difficultyStep`）。§8.3 的关卡判据同步改为「`stability` 过阈值且平均档位过阈值」。

降级机制是必需的。缺少它，用户会永久卡在挫败区。

### 7.4 调度器

纯函数：`(mastery, curriculum, today, seed, minutes) → SessionPlan`

Session 开始时一次性生成并落盘。中断可续，凭 seed 可复现。**不边练边算。**

先扣除固定的 2 分钟热身，**其余时间按下表比例分配**：

| 段落 | 占剩余时间 | 内容 |
|---|---|---|
| 热身 | 固定 2 min | 调性内化：跟唱音阶、找主音。不计分。P-2 实现为 6 道 20 秒的唱题填满 2 分钟（同一知识点、最强语境、不同 seed）；UI 层可合并呈现为一段连续跟唱 |
| 到期复习 | ~40% | `R` 最低者优先，跨轨道混排 |
| 当前焦点 | ~40% | 当前阶段正在攻的知识点，每个知识点取**离关卡最远**的模态（P-2 裁定 H：就绪度 = min(stability/阈值, 平均档位/阈值)，最小者优先；只看 stability 会让已经「记得住但没练难」的模态永不被排到） |
| 引入新点 | ~10% | 仅在前置条件满足时，一次最多 1–2 个 |
| 实战关 | ~10% | 阶段末尾的应用练习 |

若某段无内容可排（如无到期项、或未到阶段末尾），其配额按比例并入"当前焦点"。

**强制交错规则**（§2.5）：

- 同一知识点连续出现 ≤ 2 次
- 同一模态连续 ≤ 3 题
- 三条轨道必须交替，不允许单日单轨

### 7.4.1 两套难度机制的分工（不要混淆）

系统里有两套调难度的机制，作用范围和时间尺度完全不同：

| | 慢机制 | 快机制 |
|---|---|---|
| 是什么 | `variationLevel` / `contextLevel` 门控 | 2-down-1-up 阶梯 |
| 调什么 | 变异轴是否开放（§6.2）、语境强度 L0–L4（§6.1） | **单题内**参数：选项集大小、播放速度、旋律音数、音程跨度 |
| 时间尺度 | 跨天，随 `stability` 缓慢移动 | 题与题之间，即时 |
| 存哪里 | `MasteryState`，落盘 | Session 内临时状态，**不单独落盘，但由尝试窗口推导续起**（见下） |
| 依据 | §2.7 合意困难 + §2.8 变异预算 | §2.9 收敛于约 71% 正确率 |

慢机制决定"这个知识点今天以什么形态出现"，快机制在该形态内部微调，把难度稳在能力边界上。**快机制永远不修改 `variationLevel` 或 `contextLevel`。**

> **P-2 修订**（裁定 C/D）：阶梯若每场会话都从 0 档、0 连对重建，每个 (知识点, 模态) 每场只出现 1–2 次，永远凑不出「同档位连对 2 次」的升档条件，平均档位恒在 0 附近，§7.3 的升级判据与 §8.3 的关卡判据都不可达（仿真实测）。因此阶梯状态**不新增落盘字段**，但新会话从该 key 上次尝试记录推导出档位与连对计数续起（`resumeLadder(window)`，`scheduling/ladder.ts`）。为此 `Attempt.difficultyStep` 记录的是**答后**档位；还原时「升档到达」那条记录不计入连对，否则跨天会退化成 1-up。这不改变快机制的性质：仍是独立于 `variationLevel`/`contextLevel` 的快轴，只是不再每天失忆。
>
> **运行时契约**：调度器产出的 `ExerciseSpec.difficultyStep` 恒为 0；会话运行时在出题前把续起的阶梯档位写进规格（`{ ...spec, difficultyStep: ladder.step }`）再交给生成器，§7.5 的「强制降难度」也作用在这份实时规格与阶梯状态上。

### 7.5 防挫败护栏

- Session 内正确率跌破 55% → 强制降难度 + 插入已掌握知识点回血
- 某知识点连续 3 天无进展 → 触发**拆解**：加强语境、放慢速度、缩小选项集，从更简单形态重新爬升

### 7.6 用户不选练什么

界面不提供"我今天想练音程"这类自选入口。**理由**：自选会导致用户反复练自己已经会的内容，与调度器的全部设计意图冲突。唯一例外是 §6.5 的重练入口。

### 7.7 冷启动：入门分级测试

首次使用进行约 5 分钟的分级测试，用阶梯法快速定位起点。

对本程序的目标用户（会乐器但耳朵弱）尤其关键：让这类用户从"分辨高音低音"开始，第二天就不会再打开。

### 8.1 三条轨道

### 8.2 阶段与实战关

三轨并行推进，按阶段同步收口。每阶段末有实战关，不过不解锁下一阶段。

| 阶段 | 轨道内容 | 实战关 | 过关后能做到 |
|---|---|---|---|
| **P1 找到调中心**<br>约 4–6 周 | T1–T2 / H1–H2 / R1–R2 | 听 8 小节五声旋律，写出音级 + 说出拍号 | 听到简单旋律能哼准、能指出主音 |
| **P2 大调站稳**<br>约 6–8 周 | T3–T4 / H3 / R3–R4 | 听 16 小节大调旋律完整听写 | **听旋律能扒出来**（目标 1） |
| **P3 和声感**<br>约 8–10 周 | T5 / H4–H5 / R5 | 听 4 和弦循环伴奏 + 旋律，写出级数与旋律 | **听出和弦进行**（目标 2） |
| **P4 实战扒谱**<br>约 8–12 周 | T6–T7 / H6–H7 / R6–R7 | 完整"流行歌片段"，扒出和弦 + 主旋律 + 节奏 | 拿到没听过的歌能自己扒 |
| **P5 进阶** | T8 / H8 / R8 | 转调片段 | 处理转调与借用和弦 |

目标 3（视唱唱准）与目标 4（节奏听写与稳定）不是单独阶段，而是贯穿全程的"唱"模态与 R 轨，在每个阶段关卡处一并验收。

### 8.3 关卡通过条件

**三模态齐平**：该阶段全部知识点在听辨、唱、听写三个模态上的熟练度均过阈值，**且**实战关一次通过。

不允许靠听辨刷满而唱不出来（§2.4）。

**无逃生口。** 已确认：不提供"卡满 N 周强制解锁"。关卡的意义在于它不可绕过。

### 8.4 实战关音源

全部用 Web Audio 多轨合成自制（贝斯 + 和弦 + 旋律 + 简易鼓）。

**理由**：无版权风险；可精确控制难度与知识点覆盖；零加载体积。用真实录音这三点均无法做到。

### 8.5 周期的诚实说明

每天 25 分钟按调度器执行，走完 P1–P4 约需 **6–9 个月**。

不设计"三周速成"。练耳是知觉学习，需要大量试次与时间上的间隔，无捷径。程序能做的是**保证每一分钟都花在能力边界上**（自适应难度 + 到期复习 + 强制交错），而非让人在已会的题上刷两个月。

此周期预期应在首次使用时对用户明示。

## 9. 视唱闭环（最小实现）

### 9.1 音高检测

- 算法：**YIN**，运行于专用 Worker；AudioWorklet 只负责切帧并转发（见 P-4 spec §4.1）
- 48 kHz / 帧长 2048 / hop 512
- 输出：基频 f0 + 置信度

### 9.2 判定流程

不逐帧比对，而是先找**稳定段**：

1. 连续约 150 ms 置信度过阈值且 f0 波动小 → 判定"唱住了一个音"
2. 取该段 f0 中位数，与目标频率比较 cents 偏差
3. `|偏差| ≤ 50 cents`（半音的一半）判为正确

**状态（P-4a）**：有声帧为 YIN 阈值 0.15 且能量 ≥ 2 × 噪声基线；稳定段对连续有声帧做八度稳健的参考音高与约 0.18 s 平滑，偏离 > 80 音分且持续 ≥ 90 ms 或无声间隙 ≥ 60 ms 才分段，段内取最长稳定核（平滑后极差 ≤ 60 音分、漂移 ≤ 120 音分/秒、核长 ≥ 150 ms），具体规则与已知局限见 P-4 spec §3.2（`src/pitch/segments.ts`）。多目标音按顺序逐个比对、全对才算对（`src/pitch/judge.ts`）。唱题生成后整体按整八度搬进学习者音域（`src/pitch/range.ts`），生成器不变。

### 9.3 八度折叠（必需）

唱低/高一个八度判为正确。

**理由**：否则男声唱女声音区将全部判错，男性用户首日流失。

### 9.4 音域测定（必需）

首次使用录一次最低/最高舒适音，之后所有"唱"模态的目标音区落在该范围内。

**理由**：不做此步，约一半的唱题会超出用户音域。

### 9.5 明确不做

音准曲线可视化、颤音分析、进入音延迟测量、滑音检测、逐音偏差报告。这些属于"做透"方案，不在第一版范围。

### 15.1 已知缺口：音级的语境相关拼写

§4.2 的 `ScaleDegree` 枚举为 12 个音类各定一名，半音 8 定为 `le`。但唱名传统中同一音类在上行/下行语境拼写不同（半音 8 上行为 `si`、下行为 `le`；半音 6 上行为 `fi`、下行为 `se`）。和声小调（la 基）的升 7 级即半音 8，按传统应显示为 `si`，而当前枚举会显示 `le`。

**决定**：底层枚举保持 12 音类 12 名不变（作为掌握度模型的稳定 key），**语境相关拼写归为显示层问题**，在 UI 实现时由 `DisplayScheme` 依据当前调式与旋律方向决定显示字符串。底层 `ScaleDegree` 值不受影响。

此项在 T6（和声/旋律小调）进入课程前必须解决，否则该阶段的显示是错的。

## 16. P-1 实施后的修订与前向约束

P-1（音乐内核与音频引擎）已实施完毕并通过全分支终审。以下是实施过程中确认的对本 spec 的修订，以及必须带入后续阶段的约束。P-2（掌握度、调度器、课程、仿真）的修订已直接写回 §7.3、§7.4、§7.4.1、§13 并标注「P-2 修订」，其前向约束见 §16.4。

### 16.1 对 §4.2 的修订：`Chord` 结构

§4.2 声明的是 `Chord { degree: RomanNumeral, quality, inversion, extensions }`。**实际实现为 `Chord { rootDegree: ScaleDegree, quality, inversion }`，此偏离经验算确认为正确，予以保留。**

理由（对照 §8.1 课程表 H1–H8 验算）：

- **`extensions` 缺失无害**：H4 最高只到七和弦（`V7`、`Imaj7`、`ii7`、`vi7`），全部被 `ChordQuality` 的四个七和弦品质覆盖。整条 P1–P5 课程不含九/十一/十三和弦。
- **`ScaleDegree` 根音比 `RomanNumeral` 更强**：H8 要求借用和弦与副属。`V/V` = `{ rootDegree: 're', quality: 'maj' }`，借用 `♭VI` = `{ rootDegree: 'le', quality: 'maj' }`——12 个半音音级全部可表达。`RomanNumeral` 若限定为自然音级会卡住 H8。

若 P-5 之后引入爵士和声需要 `extensions`，届时扩展类型即可。

### 16.2 前向约束

以下六条是 P-1 实施中发现、必须在后续阶段处理的问题。每条都已验证过触发条件，不是猜测。

**FWD-1 · `AudioEngine.active` 无界增长（影响 P-3）**
`play()` 只往 `active` 数组 push，从不修剪；`onended` 断开了节点却不移除引用；只有 `stopAll()` 清空。P-1 内被验证页每次先调 `stopAll()` 所掩盖。P-3 会话运行时若连续播放（播题 → 等答 → 播反馈 → 下一题）而不每次 `stopAll()`，节点引用会随会话线性累积——单题约 10–20 事件 × 每事件 4–6 个节点，一次 30 分钟会话可积累上万个已断开但无法回收的 `AudioNode` 引用。
**修法**：`onended` 里 splice，或 `play()` 开头按 `endSec` 清理过期项。
**状态（P-3a，已关闭）**：每个音的最后一个分音结束时，释放该音全部节点并移出 `active`；`AudioEngine.activeCount` 供测试断言连续播放不增长。

**FWD-2 · `accent` 与「力度」变异轴争夺同一个 `gain` 字段（影响 P-2）**
`rhythm.ts` 的 `TimedOnset` 有 `accent: boolean`，而 `playback.ts` 的 `NoteSpec`/`PlaybackEvent` 只有一个 `gain: number`。§6.2 的变异轴 5「力度」也要写 `gain`。且 `TimedOnset → NoteSpec` 的桥接函数目前根本不存在。
**修法**：P-2 落地 R 轨前先定清楚合成规则（`gain = baseVelocity × accentFactor` 或其他）。现在定比事后拆便宜。
**状态（P-2b-T，已关闭）**：规则定为 `gain = velocity × (accent ? 1.0 : 0.75)`，桥接函数 `onsetsToNotes` 落在 `music/rhythm.ts`。旋律内容的每个音视为重音。

**FWD-3 · `chordToMidi` 无独立低音声部（影响 P-2/P-3 的 H6）**
现实现是密集排列的向上旋转：`inversion=2` 的 C 和弦是 `[67,72,76]`，低音从 C4 升到了 G4。这对 H6「转位与低音线听辨——扒和弦的实战关键」不够用，低音线训练需要低音待在低音区、上方声部另行排列。
**修法**：新增 voicing 函数，**不要改 `chordToMidi`**——它当前的行为对 H1–H5 是正确的。
**状态（P-2b-H，已关闭）**：新增 `voiceChord(chord, rootMidi)`（`music/chord.ts`），低音取转位指定的和弦音、位于上方声部中该音下方一个八度，上方声部原位密集；`chordToMidi` 未改。和弦题整题统一移八度落入 MIDI 36–96，不做逐音折叠，转位与低音走向因此保持不变。

**FWD-4 · 音区变异轴需要整体钳制，不只是 drone（影响 P-2）**
§6.2 的 `variationLevel 3` 开放音区（±2 个八度）后：`centerMidi` 可低至 36，使调性语境的持续低音掉到 MIDI 18（约 23 Hz）——低于人耳下限，手机扬声器根本发不出。同一个轴也抬高目标音与和弦：四音和弦 `inversion=3` 在根音之上再堆最多 +36 半音，配合 `centerMidi=84` 顶音可到 MIDI 100 上下。
**修法**：钳制做在 `centerMidi` 入口或整个 `PlaybackPlan` 上，而不是只给 drone 打补丁。
**状态（P-2b-T，已关闭）**：两层都做了。音区中心随机范围收到 MIDI 48–72；整份 plan（语境、内容、反馈）最后经 `foldPlanToRange` 八度折叠到 MIDI 36–96。属性测试对随机规格断言全部音高在区间内。

**FWD-5 · `GAP_SEC` 与 `releaseSec` 跨层不协调（影响 P-3）**
`tonalContext.ts` 的 `GAP_SEC = 0.35` 在 music 层选定，而释音尾巴 `releaseSec` 定义在 audio 层——按 §3.2 的分层契约，music 层不可能知道它。实测后果：`strings` 音色（`releaseSec = 0.45`）下，L0 终止式末尾主和弦的 `stopSec` = 2.10，而目标音在 `leadInSec` = 2.0 起音，**尾音溢入目标音 0.10 秒**。其余三种音色不溢出。
**修法**：不要回头调 `GAP_SEC`——那会让 music 层隐性耦合 audio 常量，破坏 §3.2 的边界。P-3 若发现语境撤除不干净，正解是在 audio 层做「目标音起音前淡出残留声部」。

**FWD-6 · `beatUnit` 的记谱约定靠测试而非类型钉住（影响 P-2 的 R6）**
`bpm` 的语义是「每分钟多少个 `beatUnit` 拍」，算式自洽全靠一条约定：`beatsPerBar` 必须填**记谱拍数**而非**感知拍数**。6/8 拍应填 `{ beatsPerBar: 6, beatUnit: 8 }`（六个八分音符），而非 `{ beatsPerBar: 3, beatUnit: 8 }`（指挥数的三个附点四分音符）。填错会让时值计算静默出错。
**现状**：P-1 已补一条 6/8 钉桩测试锁住该约定。P-2 实现 R6 时若要扩展复合拍，先读那条测试。

**状态（P-2b-R）**：R 轨生成器沿用该约定（6/8 填 `{ beatsPerBar: 6, beatUnit: 8 }`），并把 `resolved.bpm` 定义为感知拍速度：6/8 的一个感知拍是 3 个八分音符（`unitsPerPulse`），一个记谱单位的秒数为 `60 / bpm / unitsPerPulse`。

### 16.3 尚未闭合的验收依赖

P-1 计划的手机人耳实听（10 项）**尚未执行**，需要人类戴耳机在移动设备上完成。其中第 7 项「四种音色听感确实不同」是一条可能回流到 P-1 的验收依赖：`voice` 与 `strings` 都是正弦波、包络形状相近（慢起音 + 高延音），仅靠起音时间（70ms vs 160ms）与延音电平（0.6 vs 0.75）区分，是四者中最弱的一对。**若人耳分不出，需给二者不同的 `oscType`**——否则 §6.2 的音色变异轴有效基数会从 4 退化为 3，抗特异性训练相应打折。

### 16.4 P-2 实施后的前向约束

以下由 180 天虚拟学习者仿真与全分支终审确认，编号接 §16.2。

**FWD-7 · 阶梯制造的错与遗忘的耦合（影响 P-3 之后的参数回调）**
2-down-1-up 按设计维持约 29% 的错误率，而 §7.2 的更新规则把每个错都当遗忘处理。`LAPSE_C` 已从 0.5 调到 0.8（天天被排到的 key 原先在 stability 个位数天处封顶，P2 起的关卡阈值结构性不可达）。同一层耦合在 `difficulty` 轴上尚未处理：`DIFFICULTY_UP/DOWN = 0.08/0.02` 使 difficulty 的期望漂移为 0.08 − 0.10·p，正确率低于 80% 时 difficulty 漂向 1、答对增益趋零——阶梯的 71% 设计点恰在这条线之下。当前仿真正确率落在 0.80–0.84 所以没撞上。P-3 上线后若 `Attempt` 数据显示某些 key 的 stability 长期不涨，先查这里。

**FWD-8 · `ExerciseSpec.difficultyStep` 的运行时契约（影响 P-2b / P-3）**
调度器产出的规格里 `difficultyStep` 恒为 0（§7.4.1）。P-2b 的生成器按它映射选项集大小、播放速度、旋律音数；P-3 会话运行时**必须**在调用生成器前写入续起的阶梯档位（仿真运行器已这样做）。类型上没有东西强制这一点，P-3 的会话状态机测试要钉住它。

**FWD-9 · `resumeLadder` 的已知歧义（影响 P-3）**
尝试窗口只留 20 条。若整窗都是顶档连对，看不到「到达顶档」那条记录，连对计数的奇偶无从判断。此时档位反正不能再升，差一次无实际影响；但若日后调大 `LADDER_UP_AFTER` 或缩小窗口，要重看 `ladder.test.ts` 里那条性质测试的例外分支。

**FWD-10 · 仿真的 ladderAccuracy 衡量的不是阶梯收敛点（影响断言解读）**
180 天仿真里学习者能力一路涨到 1、跑赢阶段的难度上限；阶梯未饱和区间的正确率对档位几乎不敏感（逐档 0.80–0.86），它反映的是练习整体落在约 80–84% 的合意困难区。阶梯本身收敛于约 71% 由静态学习者（学习率归零、不动点落在档位区间内部）测试直接验证，实测 0.7071。满足 §8.2 周期的普通学习者在六个 seed 上实测 0.836–0.842，高于计划原设的 0.82 上界；把它压到 0.82 需要把 P2 完成推迟到第 130–150 天。**用户裁定（2026-10-13）**：保留 §8.2 周期，该断言的上界改为 0.85，角色明确为「合意困难区守卫」；阶梯收敛点由静态学习者测试单独守。

**FWD-11 · 焦点段的模态选择依赖关卡阈值（影响 P-3）**
裁定 H 后 `weakestModality`/`diversifiedFocusModalities` 需要当前阶段的 `GateSpec`。P-3 的会话运行时调用 `buildSessionPlan` 时阶段必须正确——分级测试（§7.7）定出的起点阶段要先落盘再排课。

**FWD-12 · 仿真里的实战关仍是替身（影响 P-5）**
`BOSS_ABILITY_THRESHOLD` 取虚拟学习者在该阶段全部 key 上的平均能力，不是实战关。P-5 落地真实关卡后，`evaluateGate` 的 `bossPassed` 入参改由关卡结果提供，仿真改用关卡的「可答性」检查。
